# Карта компетенций Middle React

Это описание первой ветки. Текущий экран расширен до двух профессий; общие темы отделены от специфики React. Актуальное поведение и состав — в [сравнении React и Vue](FRONTEND_COMPARISON.md).

Актуальная ветка от 19 октября 2026 года: **51 компетенция, 1 профессия, 9 разделов**. Это подготовленный профиль обучения. Требования конкретной компании могут отличаться; завершение карты само по себе не подтверждает уровень и не гарантирует работу.

## Как читать связи

В графе нет общего ограничения «каждую тему изучать строго после предыдущей». Git и терминал имеют независимые начала. HTML, CSS, HTTP и JavaScript находятся на одном уровне, хотя JavaScript начинается от основ программирования, а остальные — от устройства веба.

Несколько входящих стрелок означают ALL: нужны все перечисленные предпосылки. Примеры объединения:

- HTML + CSS + JavaScript → React.
- HTTP + асинхронность → запросы к API.
- REST + TypeScript → типизированный API.
- React-эффекты + типизированный API → серверные данные.
- Композиция + стили + доступность → UI-компоненты.

Общие темы существуют в одном экземпляре. Из HTTP выходят зависимости для API, отладки, безопасности и способов рендеринга. Финальный проект транзитивно включает все 51 компетенцию.

На рисунке убраны только избыточные транзитивные линии: если A → B → C, дополнительная A → C может не рисоваться. Полный список непосредственных требований остаётся в карточке и предметной модели. Сокращение не удаляет достижимость зависимостей.

## Где лежат данные и алгоритмы

- `packages/graph-domain/src/middle-react.ts` — ручной каталог: ID, раздел, предпосылки, описание, ожидаемое умение и материалы.
- `packages/graph-domain/src/knowledge-layout.ts` — размещение ELK Layered, уровни и SVG-пути линий. Каталог при размещении не изменяется.
- `apps/web/src/App.tsx` — адаптер React Flow, поиск, выбор раздела, подсветка соседей и карточка.
- `apps/web/src/SequentialPrototype.tsx` — прежний экран; не подключён к приложению.

Отрисовываются все 52 вершины. На таком объёме нет необходимости обрезать длинные соединения по видимой области. Сборка ELK загружается отдельным динамическим модулем; Vite сообщает о его крупном размере. Большие новые наборы и время загрузки ещё не измерены.

## Источники содержания

Материалы подобраны вручную, API курсов и вакансий пока не подключены. Базовые темы сверены с [MDN Curriculum](https://developer.mozilla.org/en-US/curriculum/core/), разделы React — с [React Learn](https://react.dev/learn), [управлением состоянием](https://react.dev/learn/managing-state) и [эффектами](https://react.dev/learn/escape-hatches), типизация — с [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html). Для пользовательских тестов используются [материалы Playwright](https://playwright.dev/docs/writing-tests), для производительности — [web.dev](https://web.dev/learn/performance).

Эти источники описывают технологии, а не единый стандарт профессии Middle. Общие ссылки в карточках — исходная подборка; детальные уроки, курсы, упражнения и проверка результатов добавляются следующим этапом содержания.

Размещение основано на [ELK.js](https://github.com/kieler/elkjs) и [интеграции ELK с React Flow](https://reactflow.dev/examples/layout/elkjs). [LONGEST_PATH_SOURCE](https://eclipse.dev/elk/reference/options/org-eclipse-elk-layered-layering-strategy.html) сохраняет общие уровни независимых тем.
